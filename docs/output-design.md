# Operational Output Design

The presentation layer is where data intelligence and operational grip become usable.

## Start-of-Play pattern

A strong Start-of-Play brief can contain:

1. **Position metadata**
   - source position timestamp;
   - preparation timestamp;
   - explicit snapshot/live status;
   - staleness warning where required.

2. **Headline position**
   - concise overall read;
   - high-value status cards where useful.

3. **Operational read**
   - area/service;
   - latest authoritative snapshot;
   - recent narrative evidence;
   - interpretation/grip read;
   - question to secure.

4. **Priority asks**
   - what needs confirming;
   - why;
   - owner/route if known;
   - what should be secured by the next decision point.

5. **Grip gaps**
   - missing owner;
   - missing deadline;
   - unresolved route;
   - data/narrative mismatch;
   - missing live confirmation;
   - requested update not found.

6. **First-touchpoint message**
   - short, professional summary that can support the opening of an operational call.

7. **Source note**
   - quantitative source;
   - narrative source classes;
   - timestamp;
   - limitations;
   - confirmation that identifiers were withheld where relevant.

## Core design rule

Keep four columns/concepts distinct:

> **Latest snapshot → Recent narrative → Grip interpretation → Question/action**

This structure makes it harder for an interpretation to be mistaken for a source fact.

## Public examples

Never publish a real operational brief as a showcase.

Use:
- fictional organisations;
- synthetic figures;
- fictional actions/owners;
- generic source IDs;
- no real meeting names;
- no internal file names;
- no sensitive escalation routes.
